# 前端原型设计文档

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.0 |
| 设计阶段 | W1–W2（阶段一） |
| 页面形式 | 单页应用，顶部双 Tab |
| 技术栈 | Vue3 + Vite + JavaScript + 原生 CSS |
| 适用范围 | 流式对话页面、结构化抽取页面 |
| 关联文档 | `docs/api.md`、`docs/dify-setup.md` |

> 本文档是阶段一前端实现基线。2026-11-11 已确认采用推荐方案；如后续调整布局、交互或文件结构，先更新本文档再改代码。

## 一、设计目标

1. 支撑第 1 次汇报的 10 分钟硬性检查：打开页面即可提问，流式显示回答。
2. 清楚展示 Prompt 变量效果：同一问题在“正式/简洁”之间切换后有可见差异。
3. 提供结构化抽取演示入口：粘贴公文、点击抽取、展示固定字段 JSON 和失败兜底。
4. 保持实现简单：不引入登录、数据库、路由和 UI 组件库，优先保证演示稳定。
5. 在前后端联调前，可通过演示模式独立查看完整界面和交互。

## 二、已确认方案

| 决策项 | 结论 | 原因 |
|---|---|---|
| 页面组织 | 单页 + 顶部两个 Tab | 阶段一功能少，减少路由和状态复杂度 |
| 前端框架 | Vue3 + Vite | 与培养计划一致，启动快 |
| 语言 | JavaScript | 阶段一不引入 TypeScript，降低实现成本 |
| 样式 | 原生 CSS | 不引入 UI 组件库，避免额外依赖和风格适配 |
| 路由 | 不使用 Vue Router | 两个页面用 Tab 切换即可 |
| Markdown | `marked` + `DOMPurify` | 支持代码块、表格，同时做 XSS 过滤 |
| 流式请求 | `fetch` + `ReadableStream` | 接口是 POST，`EventSource` 不支持 |
| 停止生成 | `AbortController` | 用户可中断流式请求 |
| 抽取页面 | 纳入本期前端 | 第 1 次汇报需要现场演示 |
| 演示模式 | 显式设置 `VITE_USE_MOCK=true`（默认 `false`） | 后端未完成或无网络时可评审界面和交互 |
| 接口基址 | 默认 `/api`，Vite 代理到 8080 | 开发环境避免 CORS |

## 三、整体布局

```text
┌────────────────────────────────────────────────────────────┐
│  AI 公文助手     [流式对话] [结构化抽取]      ● 演示模式      │
├────────────────────────────────────────────────────────────┤
│                                                            │
│                     当前 Tab 的内容                         │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

设计约束：

- 页面最大内容宽度约 1100px，居中显示。
- 顶部 Header 固定，Tab 切换不刷新页面。
- 切换 Tab 时保留对话页的消息和输入内容，不重新初始化。
- 桌面端优先，兼容 1280×720 和 1920×1080 演示环境。
- 窄屏（<768px）下自动单列布局。

## 四、流式对话页原型

### 4.1 页面结构

```text
┌──────────────────────────────────────────────────────────┐
│ AI 公文助手        [流式对话] [结构化抽取]     ● 演示模式   │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  ┌────────────────────────────────────────────────────┐  │
│  │ 助手                                                │  │
│  │ 你好，我是公文写作助手。请描述你要写作的内容。       │  │
│  └────────────────────────────────────────────────────┘  │
│                                                          │
│                          ┌─────────────────────────────┐ │
│                          │ 用户：写一份安全生产检查通知  │ │
│                          └─────────────────────────────┘ │
│                                                          │
│  ┌────────────────────────────────────────────────────┐  │
│  │ 助手                                                │  │
│  │ 关于...（Markdown 渲染，流式追加）                  │  │
│  │                                                    │  │
│  │ 首字 0.8s  traceId: a1b2c3d4                       │  │
│  └────────────────────────────────────────────────────┘  │
│                                                          │
├──────────────────────────────────────────────────────────┤
│ [正式 ▼] [输入写作要求...                         ] [发送] │
│ 提示：Enter 发送，Shift + Enter 换行                     │
└──────────────────────────────────────────────────────────┘
```

### 4.2 消息样式

| 消息类型 | 对齐 | 样式 |
|---|---|---|
| 用户消息 | 右对齐 | 深色气泡，纯文本展示，保留换行 |
| 助手消息 | 左对齐 | 浅色卡片，支持 Markdown |
| 错误消息 | 左对齐 | 红色边框提示卡，展示错误原因和 traceId |
| 生成中 | 左对齐 | 内容实时追加，显示光标或“生成中”状态 |

助手消息支持标题、段落、列表、行内代码、代码块、表格、粗体、斜体和引用；渲染前通过 `DOMPurify.sanitize` 过滤。

### 4.3 输入区

| 元素 | 行为 |
|---|---|
| 风格选择 | `正式` / `简洁`，对应 `style=formal/concise` |
| 输入框 | 多行文本框，最多 2000 字符，显示字数 |
| 发送按钮 | 输入为空或正在生成时禁用 |
| 停止按钮 | 生成中显示，点击后取消请求并保留已生成内容 |
| 快捷操作 | Enter 发送；Shift + Enter 换行 |
| 示例问题 | 提供“填入示例”按钮，方便演示和测试 |

### 4.4 对话状态

```text
空闲 idle
  ↓ 发送
连接中 connecting
  ↓ 收到第一个 delta
生成中 streaming
  ↓ done / error / 用户停止
完成 done / 失败 error / 已停止 stopped
```

- 空闲：发送按钮可用，输入框可编辑。
- 连接中：显示“连接中…”，发送按钮禁用，停止按钮可用。
- 生成中：助手消息逐字追加，显示首字耗时。
- 完成：显示 traceId 和总耗时。
- 失败：显示错误码、可读信息和 traceId，保留用户消息。
- 已停止：标记“已停止生成”，保留已生成内容。

### 4.5 首字耗时

- 从点击发送开始计时。
- 收到第一个 `message` 事件的 `delta` 时停止计时。
- 显示在助手消息底部，例如：`首字 0.8s`。
- 连续 5 次测试的数据记录到 `docs/streaming-test.md`。

### 4.6 错误处理

| 场景 | 页面表现 |
|---|---|
| 后端未启动 | 顶部状态变为“后端离线”，发送时提示启动后端 |
| 参数错误 `4000` | 输入框下方提示具体字段错误 |
| 模型失败 `5001` | 消息卡片显示“模型调用失败”和 traceId |
| 网络中断 | 显示“网络连接中断，请重试” |
| 用户停止 | 不显示错误，标记“已停止生成” |

错误信息不得包含模型 Key、上游堆栈或内部地址。

## 五、结构化抽取页原型

### 5.1 页面结构

```text
┌──────────────────────────────────────────────────────────┐
│ AI 公文助手        [流式对话] [结构化抽取]     ● 演示模式   │
├──────────────────────────────────────────────────────────┤
│ 公文文本                                                  │
│ ┌──────────────────────────────────────────────────────┐ │
│ │ 关于开展安全生产检查的通知                            │ │
│ │ 各部门：                                              │ │
│ │ ……                                                    │ │
│ └──────────────────────────────────────────────────────┘ │
│ [加载正常样例] [加载失败样例] [开始抽取]                   │
│                                                          │
│ 抽取结果                                                  │
│ ┌───────────────────────────┬──────────────────────────┐ │
│ │ 字段                      │ 值                       │ │
│ │ docType                   │ 通知                     │ │
│ │ title                     │ 关于...                  │ │
│ │ recipient                 │ 各部门                   │ │
│ │ signature                 │ XX办公室                 │ │
│ │ date                      │ 2026-11-01               │ │
│ ├───────────────────────────┴──────────────────────────┤ │
│ │ 原始 JSON                                             │ │
│ │ { ... }                                               │ │
│ └──────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────┘
```

### 5.2 交互流程

1. 用户粘贴公文文本，或点击“加载正常样例”。
2. 点击“开始抽取”，按钮进入加载状态。
3. 成功时展示五个字段的表格和格式化 JSON。
4. 失败时展示错误码、错误信息和 traceId，不覆盖输入文本。
5. “加载失败样例”用于演示解析失败和 `5003` 兜底。
6. 清空按钮重置输入和结果；切换 Tab 后保留结果。

### 5.3 字段展示

| 字段 | 中文名 | 空值显示 |
|---|---|---|
| `docType` | 文种 | `未识别` |
| `title` | 标题 | `未识别` |
| `recipient` | 主送单位 | `未识别` |
| `signature` | 落款 | `未识别` |
| `date` | 成文日期 | `未识别` |

原始 JSON 使用等宽字体，保留字段名和 `null`，便于验收时确认五个字段都存在。

### 5.4 抽取状态

```text
idle → loading → success
              ↘ error（4000 / 5001 / 5003 / 网络错误）
```

- 加载中：按钮显示“抽取中…”，禁用重复提交。
- 成功：绿色状态标识“抽取成功”。
- 失败：红色错误卡片，保留 traceId。
- 输入为空或超过 10000 字符：前端先提示，不发送请求。

### 6.1 文件职责

| 文件 | 职责 |
|---|---|
| `App.vue` | 维护当前 Tab、健康状态；用 `v-show` 保留两个页面状态 |
| `ChatHeader.vue` | 展示产品名、Tab、切换事件、后端/演示状态 |
| `ChatView.vue` | 组织消息列表、欢迎语、调用 `useChatStream` |
| `ChatMessage.vue` | 根据角色渲染气泡；助手消息渲染 Markdown |
| `ChatComposer.vue` | 双向绑定输入、风格、发送/停止事件和快捷键 |
| `ExtractView.vue` | 文本框、样例按钮、抽取请求、结果和错误状态 |
| `ExtractResult.vue` | 五字段表格、原始 JSON、空值和错误展示 |
| `useChatStream.js` | 管理消息、流式状态、首字耗时、错误、取消请求 |
| `api/chat.js` | fetch 流式接口，调用 SSE 解析器，转发事件回调 |
| `api/extract.js` | fetch 非流式接口，处理 HTTP 和业务错误码 |
| `api/health.js` | 获取后端健康状态 |
| `utils/sse.js` | 按空行切分事件，解析 `event:` 与 `data:` |
| `utils/markdown.js` | 统一 Markdown 渲染与 XSS 过滤 |
| `mock/mockChat.js` | 模拟正式/简洁回答、增量输出、停止和异常 |
| `mock/mockExtract.js` | 模拟正常抽取、解析失败 `5003` 和延迟 |
| `styles/main.css` | 全部视觉样式，不引入 UI 组件库 |

## 八、演示模式

默认 `VITE_USE_MOCK=false`，连接真实后端。需要演示模式时，在 `frontend/.env` 显式开启：

```bash
VITE_API_BASE_URL=/api
VITE_USE_MOCK=true
```

演示模式行为：

- 页面无需后端即可打开。
- 健康状态显示“演示模式”。
- 对话页按正式/简洁返回不同的模拟文本，并以 30–60ms 间隔增量输出。
- 输入 `[[error]]` 或在失败样例下演示模型错误。
- 抽取页对正常文本返回固定字段；包含 `[[fail]]` 的文本返回 `5003`。
- 停止按钮可以中断模拟流，保留已生成内容。

联调真实后端时改回默认值：

```bash
VITE_USE_MOCK=false
```

Vite 代理配置：

```js
server: {
  port: 5173,
  proxy: {
    '/api': 'http://localhost:8080'
  }
}
```

## 十、视觉规范

| 项目 | 建议 |
|---|---|
| 主色 | 深蓝或墨绿，用于主按钮和选中 Tab |
| 背景 | 浅灰白，内容卡片白色 |
| 用户气泡 | 主色深色背景、白色文字 |
| 助手气泡 | 白色背景、浅边框、深色文字 |
| 错误色 | 红色，仅用于错误和失败状态 |
| 成功色 | 绿色，用于成功状态和在线指示 |
| 字体 | 系统字体；代码和 JSON 使用等宽字体 |
| 圆角 | 8–12px，避免过度装饰 |
| 间距 | 8px 基准，主区块 16–24px |
| 响应式 | 768px 以下单列，输入区固定在可视区域底部 |

可访问性要求：

- 输入框和按钮有明确标签。
- 键盘可完成发送、停止、切换 Tab。
- 流式内容区域使用 `aria-live="polite"`。
- 错误信息不仅靠颜色区分，同时有文字说明。
