## 四、问题与解决

| 问题 | 原因 | 措施 / 遗留 |
|---|---|---|
| SSE 中文显示乱码 | MockMvc 默认按 ISO-8859-1 解码响应 | SSE `produces` 显式声明 UTF-8，测试按 UTF-8 读取 |
| 稀疏文本抽取返回 5003 | 校验逻辑把“全部字段为 null”误判为无效输出 | 改为“至少包含一个约定字段”即接受，缺字段返回 null；补充测试 |
| 流式长回答可能被 60 秒截断 | `HttpRequest` 的整体 timeout 覆盖整个流式响应 | 评审后仅对非流式请求设置整体超时，流式依赖连接超时与取消 |
| Docker Desktop 启动失败 | WSL 状态异常，日志提示 `WSL update required` | `wsl --shutdown` 后执行 `docker desktop restart`，再启动 Dify |
| Windows 下 `127.0.0.1:5173` 偶发不可访问 | Vite 绑定 IPv6 `::1` | README 统一使用 `localhost`，并设置 `strictPort` |

## 六、学习笔记（1 概念 + 1 踩坑 + 1 待验证问题）

- **概念：SSE（Server-Sent Events）**。服务器通过单向 HTTP 长连接持续推送 `event` / `data` 文本块，适合模型逐字输出；本项目后端用 `SseEmitter` 转发，前端用 `fetch + ReadableStream` 解析，完成后发送 `done`，异常发送 `error`。
- **踩坑：SSE 中文乱码**。现象是测试中中文显示为乱码；原因是响应编码未固定为 UTF-8；解决是 `produces = "text/event-stream;charset=UTF-8"`，测试按 UTF-8 解码。
- **待验证问题：结构化抽取对模型输出稳定性的依赖**。假设降低 `temperature` 并加强“只输出 JSON”的系统提示可减少重试；验证计划是用 20 段不同类型公文连续抽取，统计首次解析成功率与重试率。
