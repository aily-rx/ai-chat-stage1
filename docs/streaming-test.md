## 一、首字延迟（5 次）

测试问题：`用三句话介绍RAG`，`style=formal`。每次重新加载页面后从输入框发送。

| 次数 | 首字耗时 | 总耗时 | 输出字符数 | 终止事件 |
|---|---|---|---|---|
| 1 | 1.27 s | 2.12 s | 213 | `done` |
| 2 | 0.64 s | 1.35 s | 184 | `done` |
| 3 | 0.59 s | 1.24 s | 143 | `done` |
| 4 | 0.95 s | 1.78 s | 205 | `done` |
| 5 | 0.92 s | 1.84 s | 203 | `done` |

- 平均首字耗时：**0.87 s**
- 最大首字耗时：**1.27 s**
- 验收要求：最大值 ≤ 3 s，**通过**。
- 5 次均收到 `done`，未出现截断或未终止的流。

## 二、Prompt 变量对比

测试问题：`介绍一下RAG`。同一模型、同一问题，仅切换 `style`。

| 风格 | 首字耗时 | 总耗时 | 输出字符数 | 输出特征 |
|---|---|---|---|---|
| `formal` | 0.51 s | 2.05 s | 417 | 包含标题、流程编号、优势、应用和挑战，结构完整 |
| `concise` | 0.80 s | 1.07 s | 51 | 一段话直接回答，无分点、无背景铺陈 |

正式输出节选：

```text
## RAG（检索增强生成）简介
RAG 是一种将信息检索与文本生成相结合的技术架构……
**基本流程**
1. 索引构建……
2. 检索……
3. 增强生成……
```

简洁输出全文：

```text
RAG（检索增强生成）指先从知识库检索相关内容，再交由大模型生成答案，可提升准确性、时效性并减少幻觉。
```

结论：两种风格的篇幅和结构差异明显，可以用于现场演示 Prompt 变量效果。

## 三、停止生成

- 输入较长写作要求（不少于 500 字的通知），点击发送。
- 首字约 1.00 s 到达，点击“停止”。
- 前端消息状态变为 `message--stopped`，消息底部显示“已停止生成”。
- 未出现错误横幅，收到 `AbortError` 后按用户主动停止处理。
- 后端停止读取上游并释放连接，日志中未出现模型调用错误。
- 未验证项：无法从浏览器侧直接测量上游 TCP 连接关闭的确切时刻；已通过 SSE 发送失败与取消标志保证读取循环退出。

## 四、长回答不截断

测试问题（`style=formal`）：要求生成一篇不少于 1200 字的 RAG 技术说明，包含至少三个二级标题、一个完整 Java 代码块，并在最后一行输出 `【END-OF-ANSWER】`。

| 指标 | 实测结果 |
|---|---|
| 接口 | `POST /api/chat/stream` |
| 首字耗时 | 0.62 s |
| 总耗时 | 5.47 s |
| 输出字符数 | 2102 |
| delta 事件数 | 844 |
| 终止事件 | `done` |
| traceId | `92de515b` |

说明：本项通过 HTTP 客户端直连后端测试，首字为首个 SSE `delta` 到达测试客户端的耗时。

检查结果：

- 输出字符数 **2102 > 800**，满足长回答要求。
- Markdown 代码块围栏成对闭合。
- 回答末尾包含 `【END-OF-ANSWER】`，说明内容完整到达客户端。
- 未收到 `error` 事件；后端日志记录 `chat stream completed`，未出现“模型响应提前结束”。
- 完整输出与检查结果见 `docs/samples/long-answer-test.json`。

## 五、错误与参数校验

| 场景 | 结果 | 说明 |
|---|---|---|
| 空 `message` | HTTP 400，`code=4000` | `message 不能为空`，响应头含 `X-Trace-Id` |
| 非法 `style=poetic` | HTTP 400，`code=4000` | `style 只支持 formal 或 concise` |
| 请求体 JSON 不完整 | HTTP 400，`code=4000` | `请求体格式错误` |
| 模型调用失败 | SSE `event:error`，`code=5001` | 集成测试模拟上游异常，不泄露堆栈和 Key |
| 前端演示模式输入 `[[error]]` | SSE `event:error`，`code=5001` | 用于无网络时演示异常态 |
| 用户点击停止 | 前端状态 `stopped`，无错误事件 | 不展示为失败 |

所有非流式错误响应均保留统一结构：`code / message / data / traceId`。

## 六、结构化抽取

### 6.1 真实接口结果

测试文本为“关于开展安全生产检查的通知”样例，`POST /api/extract` 实测：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "docType": "通知",
    "title": "关于开展安全生产检查的通知",
    "recipient": "各部门",
    "signature": "XX办公室",
    "date": "2026-11-01"
  },
  "traceId": "7660bbd3"
}
```

| 场景 | 结果 | 耗时 |
|---|---|---|
| 完整公文 | HTTP 200，五个字段全部识别 | 约 0.91 s |
| 信息不足的短文本 | HTTP 200，五个字段均为 `null` | 约 0.99 s |
| 空 `text` | HTTP 400，`code=4000` | 即时返回 |

说明：五个字段始终存在；无法识别的字段返回 `null`，不省略字段名。

### 6.2 兜底与重试测试

自动化测试覆盖以下情况：

- 模型输出带 Markdown 围栏：去除围栏后正常解析。
- 字段缺失：缺失字段返回 `null`。
- 日期为 `2026年11月1日`：规范化为 `2026-11-01`。
- 非法日期 `2026-02-31`：按无法识别处理并返回 `null`。
- 第一次输出无法解析、第二次正常：重试一次后成功。
- 连续两次无法解析：返回 HTTP 200 与 `code=5003`，不抛未处理 500。
- 模型调用失败：返回 HTTP 200 与 `code=5001`。
- 空 JSON 对象 `{}`：视为无效输出并触发重试。

前端演示模式还提供 `[[fail]]` 文本，可直接展示 `5003` 失败卡片。

### 6.3 长文本抽取

构造一份 9367 字符的完整通知（`docs/samples/extract-long-input.json`），包含标题、主送单位、正文、落款和日期，调用 `POST /api/extract`。

| 指标 | 实测结果 |
|---|---|
| 输入字符数 | 9367（不超过 10000） |
| HTTP 状态 | 200 |
| 耗时 | 1.48 s |
| traceId | `aad7fc04` |
| `docType` | 通知 |
| `title` | 关于开展2026年第四季度安全生产大检查的通知 |
| `recipient` | 各部门 |
| `signature` | XX公司办公室 |
| `date` | 2026-11-12 |

五个字段均正确返回，日期从原文中的“2026年11月12日”规范化为 `2026-11-12`。

边界测试：输入 10001 字符时返回 HTTP 400、`code=4000`、`message=text 不能超过 10000 字符`。完整响应见 `docs/samples/extract-long-result.json`。

## 八、结论

- SSE 流式对话、停止生成、正式/简洁风格切换均通过真实 DeepSeek 联调。
- 首字延迟最大 1.27 s，满足 ≤3 s 的验收要求。
- 长回答实测 2102 字符，收到 `done`，代码块闭合且末尾标记完整，未发生截断。
- 结构化抽取五个固定字段可正常返回，解析失败重试与 `5003` 兜底已覆盖。
- 9367 字符长文本抽取五字段正确；10001 字符输入按约定返回 HTTP 400 与 `code=4000`。
- 前端默认连接真实后端（`VITE_USE_MOCK=false`）；需要无后端演示时，将 `frontend/.env` 的 `VITE_USE_MOCK` 显式设为 `true`。
- Dify 1.19.0 作为独立交付物，不参与本链路；其启动和 Chatbot 测试单独记录。
