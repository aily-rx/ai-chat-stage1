# Prompt 样例 02：简洁风格公文对话

| 项目 | 内容 |
|---|---|
| Prompt ID | `chat-concise` |
| Prompt 版本 | `v1.0` |
| 实际模板 | `backend/src/main/resources/prompts/chat-base.txt` + `chat-concise.txt` |
| 调用接口 | `POST /api/chat/stream`，`style=concise` |
| 模型 | `deepseek-chat`（可通过 `LLM_MODEL` 配置） |
| 适用场景 | 快速问答、要点提炼、需要直接给结论的公文辅助场景 |

## 1. 场景与目标

用户希望快速得到结论或关键要点，不希望阅读背景铺陈。目标是：

- 第一句直接回答问题。
- 删除重复背景和过渡语。
- 保留事实、单位、日期等必要信息。
- 在公众页面上明显区别于正式风格，用于现场演示 Prompt 变量生效。

## 2. 系统提示词

### 2.1 基础模板 `chat-base.txt`

```text
你是一名严谨的中文公文写作助手，请根据用户的写作要求输出中文内容。
要求：
1. 内容准确、结构清晰，符合中文公文表达习惯；
2. 使用 Markdown 分段，必要时使用标题、编号和列表；
3. 不要编造不存在的单位、数据或文件依据，缺失信息使用“XX单位”等占位符；
4. 直接输出正文，不要解释你的写作过程。

{{style_instruction}}
```

### 2.2 简洁风格片段 `chat-concise.txt`

```text
风格要求：简洁。直入主题，保留必要信息，删除背景铺垫和重复表述，优先使用短句。
问答类回答用一句话直接回答，不超过 50 字；撰写公文时只保留必要公文要素。
```

### 2.3 渲染结果

`PromptService` 将 `{{style_instruction}}` 替换为简洁风格片段后发送给模型：

```text
你是一名严谨的中文公文写作助手，请根据用户的写作要求输出中文内容。
要求：
1. 内容准确、结构清晰，符合中文公文表达习惯；
2. 使用 Markdown 分段，必要时使用标题、编号和列表；
3. 不要编造不存在的单位、数据或文件依据，缺失信息使用“XX单位”等占位符；
4. 直接输出正文，不要解释你的写作过程。

风格要求：简洁。直入主题，保留必要信息，删除背景铺垫和重复表述，优先使用短句。
问答类回答用一句话直接回答，不超过 50 字；撰写公文时只保留必要公文要素。
```

## 3. 变量说明

| 变量或参数 | 来源 | 作用 | 示例 |
|---|---|---|---|
| `{{style_instruction}}` | 服务端加载 `chat-concise.txt` 后替换 | 注入简洁风格要求 | 简洁风格片段 |
| `message` | 请求体 | 作为 `user` role 发送给模型 | `介绍一下RAG` |
| `style` | 请求体 | 必须为 `concise` 才选择此模板 | `concise` |
| `chat.version` | `prompt-catalog.properties` | 版本标识，写入日志 | `v1.0` |

用户消息不嵌入 system prompt；系统约束与用户输入分开，避免用户文本覆盖风格要求。

## 4. 模型参数

| 参数 | 当前值 | 说明 |
|---|---|---|
| `model` | `deepseek-chat` | 可通过 `LLM_MODEL` 覆盖 |
| `stream` | `true` | 使用 SSE 流式返回 |
| `temperature` | 未显式设置 | 使用 API 默认值 |
| `max_tokens` | 未显式设置 | 由模型默认值控制 |
| 连接超时 | 10 s | HTTP 连接超时 |
| 流式总超时 | 不设置整体超时 | 由用户停止或上游结束控制 |

## 5. 示例输入与输出

### 5.1 示例一：知识问答

输入：

```json
{
  "message": "介绍一下RAG",
  "style": "concise"
}
```

真实联调输出：

```text
RAG（检索增强生成）指先从知识库检索相关内容，再交由大模型生成答案，可提升准确性、时效性并减少幻觉。
```

测试记录：首字约 0.80 s，总耗时约 1.07 s，输出约 51 字符，结束事件为 `done`。

### 5.2 示例二：问题本身要求较长，但简洁风格压缩输出

输入：

```json
{
  "message": "用三句话介绍RAG",
  "style": "concise"
}
```

真实联调输出：

```text
RAG（检索增强生成）是结合信息检索与文本生成的技术。先从知识库检索相关文档，再交由大模型生成回答，可提升准确性与时效性、减少幻觉。
```

测试记录：首字约 0.47 s，总耗时约 0.82 s，输出约 66 字符，traceId 为 `1b903eb6`。

这组输入同时暴露了一个限制：用户要求“三句话”，而简洁 Prompt 又要求“一句话、不超过 50 字”。模型选择了一句话，但 66 字超过了 Prompt 中的软约束，说明**长度要求不能只依赖 Prompt**。阶段一保留该真实记录；后续可在模型调用层增加 `max_tokens` 或在应用层做长度校验。

## 6. 设计理由

1. **一句话约束**：同一切换变量能产生肉眼可见的输出差异，适合汇报现场演示。
2. **保留必要事实**：简洁不等于删除单位、日期等关键信息。
3. **共享基础模板**：与正式风格共享角色、防编造、Markdown 和“不解释过程”约束，降低维护成本。
4. **软约束要如实说明**：Prompt 中的长度限制不是强保证，仍需回归测试或代码层校验。

## 7. 失败案例与改进

### 7.1 真实失败现象

输入要求三句话，模板要求一句话且不超过 50 字，实际输出 66 字：

```text
RAG（检索增强生成）是结合信息检索与文本生成的技术。先从知识库检索相关文档，再交由大模型生成回答，可提升准确性与时效性、减少幻觉。
```

原因是输入指令与风格指令存在冲突，且长度限制只是自然语言约束。模型优先满足了简洁风格，但没有严格满足字数和句数要求。

### 7.2 改进方向

| 改进 | 说明 | 是否已在阶段一实现 |
|---|---|---|
| Prompt 中明确优先级 | 说明当用户句数要求与风格长度冲突时，以用户明确要求为准 | 未实现，建议后续补充 |
| 应用层长度校验 | 对简洁回答做字符数检测，超限时提示或重试 | 未实现 |
| `max_tokens` 限制 | 在调用层限制输出 token 数，只能限制上限，不能保证句子数 | 未实现 |
| 输入改写 | 前端或后端把“三句话”改成单句问题，不改变用户原意 | 未实现 |

该案例是真实联调记录，不伪造“改进后一定通过”的结论。阶段一的目标是演示风格变量可见有效，同时如实暴露 Prompt 软约束的边界。

## 8. 版本变更规则

- 修改 `chat-base.txt` 或 `chat-concise.txt` 后，更新 `chat.version`。
- 如果调整长度策略，必须在 `docs/streaming-test.md` 增加新的真实对比记录。
- 日志中的 `promptId=chat-concise`、`promptVersion` 用于区分不同版本的输出。
